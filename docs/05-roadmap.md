# 05 · Roadmap

Order rule: **build the reference before the thing it checks.** The
interpreter and test harness come before the recompiler, so the recompiler is
never judged against itself. Each milestone has an exit test; it is "done"
only when that test passes in CI.

## Layout
```
retrocast/
  CMakeLists.txt           build defaults, SDL3, frontend(), ROMS / FDS_BIOS / AUTO_HINTS ...
  cmake/                   SDL3 build options
  core/                    shared by every system
    input_log.c            input recordings, pad bits
    frontend/              sdl3_main.c settings.c tv_frame.c, system.h (a system's interface)
    recomp/                template.c: instruction templates, PC markers (every recompiler)
  nes/                     the NES and the Famicom Disk System
    CMakeLists.txt         nes_recompile(), nes, nes_headless, nesrecomp
    recomp/                nesrecomp: ops.c (opcode table), c6502.c (C per opcode),
                           analyze.c (decode, blocks, banks), emit.c, main.c
    runtime/
      cpu.h cpu_ops.h cpu.c  CPU core (switch generated by nesrecomp)
      nes.c ppu.c apu.c cart.c fds.c palette.c
      recomp_rt.h          interface to recompiled code (recomp_none.c: none)
    frontend.c             the NES for core/frontend (system.h)
    tests/                 cpu_tests.c nes_headless.c
    games/<name>.toml      per-game hints (entry points, banked entries; fds.toml: the BIOS)
  gb/                      the Game Boy (not recompiled yet)
    CMakeLists.txt         gbrecomp, gbcpu, gb_cpu_tests
    recomp/                gbrecomp: sm83.c (C per opcode), main.c
    runtime/               cpu.h cpu_ops.h cpu.c, gb.c (bus, timer, interrupts, DMA, states), ppu.c, cart.c (MBCs)
    frontend.c             the Game Boy for core/frontend (system.h)
    tests/                 cpu_tests.c (SingleStepTests sm83), gb_headless.c (test ROMs)
  tests/                   Python unittest suite, fetch_test_roms.py
  tools/                   bench.py, smoke_games.py, import_r2_6502.py, make_release.py
  dist/                    README.txt for the release archives
  docs/
```
The first plan had per-mapper files and a Python recompiler; the
recompiler was Python until M8a. The retired first prototype is described
in [08](08-first-prototype.md).

## M5 · Recompiler v1
Python until M8a.
- [x] Blocks and C emitter, with hints.
- [x] Runtime dispatch (`nes_step`): block if recompiled, else interpreter;
  PRG-hash check; fallback statistics.
- [x] `nes_headless --diff` (lockstep vs interpreter: CPU, RAM, PRG RAM, PPU
  state per block, frame image per frame) and `--misses`.
- [x] Feedback loop: misses become hints (`nes/games/battle_city.toml`).
- [x] CMake: `nes_recompile()`; nestest always, your own ROMs via `-DROMS=`
  (`NES_GAMES` until M11).
- [x] Recompiled nestest: all 3,752 block-boundary states match nestest.log.
- [x] Battle City: 10 minutes of scripted play, zero divergences, zero
  interpreted instructions.
- **Exit:** met.

M5b, speed:
- [x] `tools/bench.py`: best of 3 runs (desktop timings vary ±20%).
- [x] Lazy PPU catch-up (`nes.c`): dots are counted and run in batches when
  the CPU touches the PPU, OAM DMA runs, or vblank (NMI) is due.
- [x] `ppu_run`: skips vblank lines in one step; sprite line buffer
  (per-pixel lookup instead of scanning 8 sprites).
- [x] Memory-map fast path in `rd`/`wr` (`cpu.h` read/write maps): RAM,
  PRG RAM and ROM accesses are inline loads; helps both modes.
- [x] Recompiled code with static PC: code bytes and PC values are constants
  (`fetch_k`).
- Result (6,000 frames, best of 3): interpreter 27.7x → 31.0x real time,
  recompiled 18.5x → 30.5x. CPU side alone (PPU stubbed): recompiled
  1.8x faster than the interpreter (123x vs 69x real time). The PPU is
  ~75% of the time in both modes, so overall they are at parity.

## M7 · Mappers

- [x] M7a: mappers 0, 1 (MMC1, incl. SUROM 512 KB and the ignored
  consecutive write), 2, 3, 4 (MMC3 rev B with A12-clocked IRQ), 7, 11, 66.
  PPU sprite fetches spread over dots 257-320; every PPU bus address
  reported to the cart (A12). Mapper writes catch up the PPU first
  (mid-frame bank switches); PRG fast-path pages follow the bank tables.

## M8 · Tooling and polish
M8a, the recompiler in the build:
- [x] Recompiler ported from Python to C (`nesrecomp`, `nes/recomp/*.c`); its
  output byte-identical to the Python version's for nestest and the 8 test
  games, and so is the interpreter switch it writes. The build needs no
  Python; the tests still use it.
- [x] The generated C embeds the whole ROM; the executables run without a
  ROM path (data is read through unbounded pointers, so nothing is left out).
- [x] `AUTO_HINTS` (on by default): the build traces each game in the
  interpreter (`nes_headless --play 1 --misses`, `AUTO_HINTS_FRAMES`) and
  gives the trace to `nesrecomp --misses`; one pass, no rebuild loop.
- [x] Python tests drive `nesrecomp` (`tests/nesrecomp.py`); the scripted
  play became `nes_headless --play`.
- **Exit:** met (06).

M8b:
- [x] Coverage report: `nes_headless --coverage`: CPU cycles in recompiled
  code vs interpreted ROM, RAM code and interrupt entries.
- [x] Save states: one format for interpreter and recompiled builds;
  `--save-state/--load-state` in nes_headless (also with `--diff`), F2/F4

- [x] Frame-hash regression suite (`tests/test_regression.py`): frame, CPU

- [x] Frontend: no console window on Windows; `<program>.ini` settings

- [x] Release is the default build type.
- **Exit:** met (06).

M8c, open items:

- [x] `EMBED_ROM=OFF`: programs without the ROM inside.
- [x] DMA rework, apu_reset harness fix, straddling instructions, CI file.
- [x] Release archives with a kit (`tools/make_release.py`, a workflow on

- [x] Frontend: colour emphasis, overscan (top/bottom and sides), pixel

## Speed passes
Found by sampling profiles; each keeps the output identical (06).
- [x] After M7b: bus helpers out of line in generated code, block chaining
  (`RECOMP_CHAIN`, +2-3%), a PPU fast path for visible dots, a mixer
  cache. Kirby recompiled 19.2x → 32.6x real time.
- [x] After M11: FDS's low-pass stuck on denormals (FDS games 2.5x
  slower); the APU steps quiet runs of cycles at once; the PPU draws a
  tile at a time (8 palette indices in one 64-bit word for
  background-only tiles), sprite evaluation and fetches in tight loops;
  one RAM check per FDS block and an O(1) RAM code lookup. Air Fortress
  17.2x → 34.8x recompiled, Zelda no Densetsu 14.6x → 23.9x.
- [ ] FDS sound costs the most in FDS games (its channel and low-pass every
  cycle); cheaper filter math would change the output bits.

## Stretch
- JIT for code in RAM or found at run time. With play-to-recompile and auto
  hints, ROM code is above 99.9% recompiled in the test games and FDS RAM
  code is recompiled per disk file, so a JIT has little left to gain.
- Analysis build: symbols per block for IDA/Ghidra, with a write-up.
- Hand-written x86-64 backend, checked against the C backend with `--diff`.
