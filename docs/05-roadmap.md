# 05 · Roadmap

Order rule: **build the reference before the thing it checks.** The
interpreter and test harness come before the recompiler, so the recompiler is
never judged against itself. Each milestone has an exit test; it is "done"
only when that test passes in CI.

## Target layout
```
nes/
  CMakeLists.txt
  recomp/            nesrecomp (C, since M8a): ops.c, c6502.c (C per opcode),
                     analyze.c (decode, blocks, banks), emit.c, main.c
  tools/             import_r2_6502.py, bench.py, smoke_games.py
  runtime/
    cpu.h cpu_ops.h cpu.c   CPU core (switch generated by nesrecomp)
    nes.c ppu.c apu.c cart.c palette.c input_log.c
    platform/ sdl3_main.c settings.c tv_frame.c
    tests/    cpu_tests.c nes_headless.c
  games/<name>.toml       per-game hints (extra entry points, banked entries)
  tests/                  Python unittest suite, fetch_test_roms.py
  docs/
```
(The layout as built; the first plan had per-mapper files and a Python
recompiler.)

## M5b · Speed
- [x] `tools/bench.py`: best of 3 runs (desktop timings vary ±20%).
- [x] Lazy PPU catch-up (`nes.c`): dots are counted and run in batches when
  the CPU touches the PPU, OAM DMA runs, or vblank (NMI) is due.
- [x] `ppu_run`: skips vblank lines in one step; sprite line buffer
  (per-pixel lookup instead of scanning 8 sprites).
- [x] Memory-map fast path in `rd`/`wr` (`cpu.h` read/write maps): RAM,
  PRG RAM and ROM accesses are inline loads; helps both modes.
- [x] Recompiled code with static PC: code bytes and PC values are constants
  (`fetch_k`, `emit_c.static_body`).
- Result (6,000 frames, best of 3): interpreter 27.7x → 31.0x real time,
  recompiled 18.5x → 30.5x. CPU side alone (PPU stubbed): recompiled
  1.8x faster than the interpreter (123x vs 69x real time). The PPU is now
  ~75% of the time in both modes, so overall they are at parity.
- [x] Faster PPU (open items pass): a specialized loop for dots 1-256 of
  rendering lines; checked by the test ROMs and frame hashes (06).

- [x] Battle City by ear: "sound is perfect" (user, 2026-11-15).
- **Exit:** met except the pending items above.

M7b (recompiler):
- [x] Bank-aware regions (`recomp/analyze.c`): code compiled per (PRG bank,
  window unit: 8 KB for MMC3, 16 KB for MMC1/UxROM, 32 KB for AxROM/Color

## M8 · Tooling and polish
M8a (recompiler in the build):
- [x] Recompiler ported from Python to C (`nesrecomp`, `recomp/*.c`); its
  output is byte-identical to the Python version's for nestest and the 8
  test games, and so is the interpreter switch it writes. The build needs
  no Python; the tests still use it.
- [x] The generated C embeds the whole ROM; the executables run without a
  ROM path (data is read through unbounded pointers, so nothing is left out).
- [x] `-DNES_AUTO_HINTS=ON`: the build traces each game in the interpreter
  (`nes_headless --play 1 --misses`, `NES_AUTO_HINTS_FRAMES`) and gives the
  trace to `nesrecomp --misses`; one pass, no rebuild loop.
- [x] Python tests that imported `recomp/` now drive `nesrecomp`
  (`tests/nesrecomp.py`); `tests/play_script.py` became `nes_headless --play`.
- **Exit:** met (06).

M8b:
- [x] Coverage report: `nes_headless --coverage` (and in `--misses`): CPU
  cycles in recompiled code vs interpreted ROM, RAM code and interrupt
  entries.
- [x] Save states: `nes_state_save/load` (runtime/nes.c), one format for
  interpreter and recompiled builds; `--save-state/--load-state` in
  nes_headless (also with `--diff`), F2/F4 in the frontend. Shortcut: the
  struct is stored raw, so states do not survive a change of its layout.
- [x] Frame-hash regression suite (`tests/test_regression.py`): frame, CPU
  cycles and audio after 3,000 scripted frames, per configured game.
- [x] Frontend: no console window on Windows; `<program>.ini` settings
  (fullscreen, fit/integer/stretch scaling, TV frame, window size); TV frame
  drawn procedurally (`runtime/platform/tv_frame.c`).
- [x] Release is the default build type.
- **Exit:** met (06).

## Open items pass (after M8)
- [x] Play-to-recompile: recompiled games write `<program>.misses`; the next
  build recompiles what was interpreted (setting `record_misses`).
- [x] `-DNES_EMBED_ROM=OFF`: programs without the ROM inside.
- [x] Speed, found by sampling profiles: bus helpers out of line in
  generated code, block chaining, PPU fast path, mixer cache (06).
- [x] DMA rework, apu_reset harness fix, straddling instructions, CI file.
- [ ] Not done: JIT (stretch). With play-to-recompile and auto hints, ROM
  code is >99.9% of cycles recompiled in all test games; what is left is
  RAM code (<0.05%), so a JIT has little to gain here.
